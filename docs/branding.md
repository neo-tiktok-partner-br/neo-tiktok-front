## 0. OBJETIVO DESTE DOCUMENTO

Este documento transforma a afinidade visual com o ecossistema TikTok em um sistema próprio, reproduzível e auditável.

A intenção **não é copiar interfaces, campanhas, composições, ilustrações, componentes ou ativos do TikTok**. A intenção é construir uma linguagem que seja imediatamente compatível com o universo de social commerce, creators, vídeo vertical e operação digital — mas que permaneça reconhecível como tecnologia, produto e comunicação da **NEØ / neoflowoff.agency**.

Este arquivo é a fonte de verdade para:

- identidade visual;
- design tokens;
- tipografia;
- cor;
- layout;
- iconografia;
- fotografia;
- motion;
- componentes de UI;
- visualização de dados;
- apresentações;
- peças de conteúdo;
- linguagem de interface;
- uso de marcas de terceiros;
- critérios anti-cópia;
- governança e QA visual.

Qualquer peça que contradiga este documento precisa ser corrigida ou submetida a revisão antes de publicação.

# 1. POSICIONAMENTO VISUAL

## 1.1 Definição

A identidade deve transmitir simultaneamente:

1. **descoberta** — conteúdo, creators, movimento, cultura;
2. **comércio** — produto, catálogo, conversão, operação;
3. **infraestrutura** — APIs, dados, eventos, automação, integrações;
4. **clareza** — software utilizável, não ficção científica;
5. **propriedade** — presença inequívoca da NEØ sem disputar atenção com o conteúdo.

A fórmula visual é:

```text
SOCIAL COMMERCE
+ SOFTWARE OPERACIONAL
+ INFRAESTRUTURA NEØ
- ESTÉTICA CORPORATIVA GENÉRICA
- CYBERPUNK
- CLONE DE TIKTOK
= SISTEMA VISUAL PROPRIETÁRIO
```

## 1.2 Sensação desejada

A primeira leitura deve ser:

> “Isso pertence naturalmente ao universo TikTok Shop.”

A segunda leitura deve ser:

> “Mas isso claramente não foi feito pelo TikTok.”

A terceira leitura deve ser:

> “Existe uma infraestrutura própria por trás.”

Se a ordem dessas três leituras se inverter, o sistema está perdendo eficiência.

# 2. DOUTRINA ANTI-CÓPIA

## 2.1 Regra central

**Referenciar a categoria. Nunca reproduzir a execução.**

Podemos absorver princípios visuais amplos presentes no ecossistema TikTok — alto contraste, energia, vídeo vertical, preto, branco, cores elétricas, hierarquia direta, interfaces com sensação de mídia — porque eles fazem sentido para a categoria.

Não podemos transformar uma página, campanha ou produto do TikTok em template.

## 2.2 O que pode inspirar

É permitido usar como referência conceitual:

- predominância de preto e branco;
- contraste alto;
- módulos grandes;
- tipografia sans de alta legibilidade;
- fotografia de creators e produtos;
- recortes verticais 9:16;
- interfaces com sensação de conteúdo em movimento;
- cores elétricas pontuais;
- linguagem de ação curta;
- composições assimétricas;
- convivência entre conteúdo e dados.

Esses elementos devem ser reconstruídos através dos tokens e componentes próprios definidos neste documento.

## 2.3 O que é proibido reproduzir

Não reproduzir, por aproximação ou reconstrução:

- homepage do TikTok Shop;
- hero do Partner Center;
- hero do SoundOn;
- ordem e posição de elementos de páginas oficiais;
- composição de cards orbitando um headline;
- formas de fundo exclusivas identificáveis;
- ilustrações oficiais;
- screenshots oficiais como decoração de produto;
- combinação exata de cor, tipografia, espaçamento e CTA de uma peça oficial;
- botões, menus, controles ou cards com aparência indistinguível dos oficiais;
- animações copiadas frame a frame;
- headline ou slogan oficial convertido em copy própria;
- ícones redesenhados a partir de ícones proprietários;
- logotipo TikTok usado como componente decorativo recorrente;
- co-branding inventado;
- qualquer composição que possa ser confundida com uma página operada pelo TikTok.

## 2.4 Similarity Gate

Antes de aprovar uma tela, hero, anúncio ou slide, o designer deve verificar os oito sinais abaixo.

Uma peça **falha automaticamente** se reproduzir uma referência oficial específica e acumular **3 ou mais sinais simultaneamente**:

1. mesma arquitetura de hero;
2. mesma posição relativa de headline e mídia;
3. mesma dupla cromática principal;
4. mesma forma de background;
5. mesma proporção e disposição de cards;
6. mesmo tipo de CTA;
7. tipografia visualmente equivalente;
8. mesma cadência textual / construção de headline.

**Meta interna:** máximo de 2 sinais coincidentes e nenhuma equivalência estrutural clara.

## 2.5 Teste de silhueta

Desfoque a peça até os textos e imagens se tornarem ilegíveis.

Se a silhueta ainda parecer uma reprodução óbvia de uma tela oficial conhecida, **reprovar**.

## 2.6 Teste sem logotipo

Remova temporariamente todos os logos.

A peça deve continuar parecendo NEØ por causa de:

- tipografia;
- ritmo;
- grid;
- Acid Green;
- tratamento de borda;
- linguagem de dados;
- microdetalhes;
- sistema de labels;
- comportamento de motion.

Se a identidade depender exclusivamente do logo, ela ainda não é uma identidade.

# 3. RELAÇÃO COM A MARCA TIKTOK

## 3.1 Princípio

TikTok, TikTok Shop e marcas relacionadas são ativos de terceiros.

Este Design System trata esses ativos como **recursos controlados**, nunca como matéria-prima livre de design.

## 3.2 Política de uso

1. Usar somente logos, ícones e asset packs oficiais quando houver necessidade legítima e permissão aplicável.
2. Nunca redesenhar, distorcer, recolorir ou “melhorar” uma marca oficial.
3. Nunca criar um logo híbrido NEØ + TikTok.
4. Nunca fundir o símbolo Ø com o símbolo TikTok.
5. Nunca colocar o logotipo TikTok como marca dominante de produto próprio.
6. Nunca sugerir que uma interface NEØ é uma tela oficial TikTok.
7. Nunca usar expressões como **“oficial”**, **“certificado”**, **“aprovado”**, **“autorizado”** ou equivalentes sem correspondência documental com o status vigente.
8. Quando houver autorização de co-branding, seguir prioritariamente os assets e regras fornecidos pelo TikTok para aquele programa, mercado e finalidade.
9. Quando uma regra externa for mais restritiva que este documento, **a regra externa prevalece**.

## 3.3 Denominação pública

O nome do TikTok deve funcionar como **referência de plataforma/ecossistema**, não como identidade proprietária da NEØ.

Preferência de construção em materiais públicos:

```text
NEØ [produto/recurso]
Integração / infraestrutura para TikTok Shop
```

Em documentação técnica, nomes oficiais de APIs, escopos, endpoints, objetos e produtos podem ser usados de forma descritiva quando necessários para precisão.

## 3.4 Área de segurança de marca

Quando um logo oficial for utilizado:

- usar o arquivo oficial;
- respeitar clear space definido pelo asset oficial;
- não aplicar efeitos;
- não inserir dentro de badge próprio;
- não usar como pattern;
- não recortar;
- não colocar em background que prejudique contraste;
- não posicionar próximo ao logo NEØ de forma que pareça um lockup oficial, salvo autorização específica.

## 3.5 Nota jurídica operacional

Este documento estabelece política interna de design, **não substitui aconselhamento jurídico** nem contratos vigentes com plataformas.

Toda campanha, produto ou peça que use marca de terceiro em contexto sensível deve ser validada contra:

- contrato vigente;
- Partner Center;
- documentação oficial;
- autorizações concedidas;
- regras locais aplicáveis.

# 4. DNA VISUAL NEØ

A identidade é construída sobre cinco assinaturas proprietárias.

## 4.1 Acid Signal

O **Acid Green `#D7FE09`** é a assinatura cromática da NEØ.

Não é cor de preenchimento indiscriminado. É um **sinal de sistema**.

Usos preferidos:

- status “connected / live / synced”;
- cursor / active marker;
- linha de infraestrutura;
- dado-chave;
- pequena superfície de CTA proprietário;
- selo NEØ;
- badge técnico;
- nó de diagrama;
- indicadores de automação;
- foco e seleção;
- assinatura final de slide.

Evitar:

- hero inteiro verde;
- parágrafos verdes;
- grandes backgrounds verdes;
- gradientes neon;
- glow excessivo.

## 4.2 Hard Contrast

O sistema nasce em contraste preto/branco.

Cor entra depois da estrutura.

## 4.3 Operational Labels

Labels curtas e técnicas são parte da estética.

Exemplos:

```text
CONNECTED
SHOP SYNC
CREATOR LAYER
ORDER EVENT
LIVE
API READY
WEBHOOK ACTIVE
SELLER 03
SYNC 12:42:18
```

Elas devem ser funcionais ou semanticamente plausíveis. Nunca usar “tech gibberish” decorativo.

## 4.4 Structured Asymmetry

Layouts podem ser assimétricos, mas nunca aleatórios.

A assimetria deve ser sustentada por grid.

## 4.5 Visible Infrastructure

A tecnologia pode aparecer visualmente por meio de:

- linhas de conexão;
- eventos;
- pequenas tabelas;
- traces;
- status;
- timestamps;
- nós;
- cards de integração;
- relações seller → connector → service;
- creator → content → order;
- shop → inventory → event.

A infraestrutura é mostrada como **produto real**, não como ficção científica.

## 5.5 Proporção cromática recomendada

Em uma composição padrão:

```text
70–85% neutrals
10–20% white/canvas contrast
2–6% ecosystem accents
1–3% Acid Green
```

Não aplicar a fórmula mecanicamente. Ela existe para impedir carnaval cromático.

## 5.6 Contraste e acessibilidade

Regras mínimas:

- texto normal: buscar **WCAG AA 4.5:1**;
- texto grande: mínimo **3:1**;
- componentes e indicadores relevantes: mínimo **3:1** contra adjacências;
- nunca depender apenas de cor para comunicar estado.

Decisões específicas:

- `#D7FE09` funciona muito bem sobre superfícies escuras;
- em superfícies claras, usar Acid como preenchimento, detalhe ou marcador — não como texto de corpo;
- `neo.pulse.500 #DD234D` pode receber texto branco para CTA quando o tamanho/peso permitir AA; validar o componente final;
- `neo.relay.500` deve ser usado principalmente sobre fundo escuro ou como elemento gráfico, não como texto pequeno em fundo branco.

- labels;

```text

```

## 7.3 Grid mobile

```text
columns: 4
gutter: 16px
margin: 16px
```

## 7.4 Regra 60/40

Em páginas narrativas, preferir relações assimétricas como:

- 7/5;
- 8/4;
- 5/7;
- 4/8.

Evitar a repetição constante de 6/6 centralizado, que tende ao genérico.

## 7.5 Full bleed

Imagem ou vídeo podem romper o container em áreas editoriais, desde que:

- exista pelo menos um eixo alinhado ao grid;
- texto principal permaneça no container;
- o rompimento seja intencional;
- a composição continue legível em 1440, 1024, 768 e 390 px.

## 7.6 Ritmo vertical

Seções de marketing:

```text
Desktop: 112–160px top/bottom
Tablet:   80–112px
Mobile:   64–88px
```

Dashboards:

```text

Mobile: 16–24px
```

# 9. RADIUS, BORDAS E ELEVAÇÃO

## 9.1 Radius

```text
radius.xs   6px    chips compactos
radius.sm   10px   buttons / inputs
radius.md   14px   cards pequenos
radius.lg   20px   cards editoriais
radius.xl   28px   mídia / hero panels
radius.pill 999px  chips / status / CTA específico
```

### Regra proprietária

A NEØ evita “everything pill”.

Pill é componente semântico, não linguagem universal.

## 9.2 Bordas

Dark:

```css
border: 1px solid rgba(255,255,255,.10);
```

Light:

```css
border: 1px solid rgba(5,5,5,.10);
```

Selected:

```css
border-color: rgba(215,254,9,.72);
```

## 9.3 Sombras

Evitar sombra pesada e difusa.

Preferir separação por superfície + borda.

Quando necessária:

```css
box-shadow:
  0 1px 2px rgba(0,0,0,.12),
  0 12px 32px rgba(0,0,0,.18);
```

## 9.4 Glow

Glow é proibido como tratamento global.

Exceção: microfeedback de estado ativo.

```css
box-shadow: 0 0 0 4px rgba(215,254,9,.10);
```

# 10. COMPONENTES BASE

## 10.1 Buttons

### Primary NEØ

- fundo: `neo.acid.500`;
- texto: `neo.void.1000`;
- radius: 10px;
- altura: 44–48px;
- peso: 600;
- sem ícone quando a ação já é inequívoca.

### Commerce Action

- fundo: `neo.pulse.500`;
- texto: branco quando contraste validado;
- reservado a ações comerciais prioritárias.

### Secondary

- fundo transparente;
- border 1px;
- texto de alto contraste.

### Ghost

- sem borda;
- hover com surface tint.

### Proibido

- botão visualmente idêntico ao CTA oficial de uma referência TikTok;
- gradiente;
- glow;
- três CTAs primários na mesma viewport.

## 10.2 Inputs

```text
height: 44–48px
radius: 10px
padding-x: 14–16px
border default: 1px
focus ring: Acid 2px + offset 2px
```

Estados obrigatórios:

- default;
- hover;
- focus;
- filled;
- disabled;
- error;
- success quando necessário.

## 10.3 Cards

Quatro famílias:

### A. Operational Card

Para status, dados e operação.

- radius 14px;
- densidade média;
- label + valor + metadata;
- sem imagem decorativa.

### B. Commerce Card

Para produto, order, shop, GMV, comissão.

- imagem opcional;
- preço/dado em destaque;
- Pulse como accent permitido.

### C. Creator Card

- thumbnail vertical ou avatar;
- handle;
- categoria;
- métricas;
- Relay como accent permitido.

### D. Infrastructure Card

- service name;
- status;
- endpoint/event;
- timestamp;
- Acid como assinatura preferencial.

## 10.4 Badges

Badges devem comunicar algo real.

Aprovados:

```text
LIVE
CONNECTED
PENDING
SYNCED
ACTION REQUIRED
CREATOR
SELLER
SHOP
EVENT
```

Proibidos:

```text
NEXT GEN
REVOLUTIONARY
AI POWERED
WEB3 READY
```

...quando usados apenas como decoração.

## 10.5 Tables

- cabeçalho 12–13px semibold;
- row 44–52px;
- zebra striping opcional e extremamente sutil;
- números alinhados à direita;
- nomes e labels à esquerda;
- status como badge;
- ações no final;
- sticky header em datasets longos;
- densidade ajustável em produto avançado.

## 10.6 Navigation

Desktop:

- logo NEØ / produto à esquerda;
- áreas principais no centro ou imediatamente após marca;
- conta/contexto à direita;
- active state com contraste + pequeno indicador Acid.

Mobile:

- reduzir destinos;
- priorizar contexto atual;
- nunca copiar a barra inferior do aplicativo TikTok.

# 11. ICONOGRAFIA

## 11.1 Linguagem

- stroke regular;
- geometria simples;
- terminais levemente arredondados;
- espessura 1.75–2px em 24px;
- sem pseudo-3D;
- sem neon.

## 11.2 Biblioteca

Preferir uma biblioteca aberta consistente, como **Lucide**, com customizações mínimas e documentadas.

Não misturar 3 famílias de ícones no mesmo produto.

## 11.3 Ícones proprietários

Podem existir para objetos de domínio:

- connector;
- shop node;
- creator node;
- event stream;
- inventory sync;
- order relay;
- webhook;
- agent.

Esses ícones devem nascer de geometria própria e não de redesenho de ativos TikTok.

## 11.4 Símbolo Ø

O Ø funciona como marca NEØ e marcador proprietário.

Pode aparecer:

- favicon;
- app icon;
- assinatura de loading;
- node central de diagramas;
- empty states proprietários.

Não deve ser fundido a ícones de terceiros.

- contraste natural;
- pretos profundos sem esmagar detalhe;

Quando usados para explicar uma funcionalidade:

- não ocultar origem a ponto de parecer UI própria;
- aplicar apenas transformações necessárias para enquadramento e privacidade;
- respeitar direitos e regras aplicáveis.

# 13. ILUSTRAÇÃO E 3D

Ilustração entra onde fotografia ou UI não explicam melhor.

# 14. MOTION SYSTEM

## 14.1 Princípio

Motion comunica **estado, continuidade e fluxo**.

Não serve para provar que sabemos animar.

## 14.2 Timings

```text
micro      120–160ms
standard   180–240ms
panel      260–360ms
narrative  450–700ms
```

## 14.3 Easing

Padrão:

```css
cubic-bezier(.2,.8,.2,1)
```

Entrada curta:

```css
cubic-bezier(.16,1,.3,1)
```

## 14.4 Movimentos proprietários

### Relay

Um evento percorre uma linha e ativa o próximo nó.

Uso:

- API;
- webhook;
- order event;
- sync;
- automação.

### Pulse Lock

Status muda de neutro para Acid e estabiliza.

### Stack Shift

Cards se deslocam 4–12px em profundidade ao mudar contexto.

### Vertical Snap

Conteúdo 9:16 entra com movimento curto vertical, sem imitar o gesto ou UI do feed TikTok.

## 14.5 Proibido

- transição idêntica ao app TikTok;
- animação de likes/corações copiada;
- ícones flutuantes imitando interface de vídeo;
- som de marca de terceiros;
- autoplay sonoro.

## 14.6 Reduced motion

Todo motion não essencial deve respeitar:

```css
@media (prefers-reduced-motion: reduce)
```

# 33. DARK E LIGHT MODE

- Void;
- white type;
